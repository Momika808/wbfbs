# wbfbs

Сборка FBS-поставок Wildberries из терминала: заказы → поставка → короба →
стикеры коробов и этикетки заказов в готовый PDF → QR поставки.

![Этикетка WB из песочницы](demo/label_33528.png) То, чего нет
в интеграционных модулях (вендоры четырёх крупнейших Bitrix-модулей прямо
отвечали покупателям «такой возможности нет») и ради чего сборщики вручную
кликают кабинет.

Работает только с **личным API-токеном селлера** на его же машине/сервере —
без передачи токена третьим лицам (требование правил WB) и без облачного
посредника: данные никуда не уходят.

## Установка

```bash
uv venv && uv pip install -e .
wbfbs ping   # проверка токена (лимит 3 запроса / 30 с)
```

Токен берётся (по приоритету): аргумент `token=` → env `WB_TOKEN` →
macOS Keychain, запись `wb-fbs-token` (имя переопределяется через
`WB_KEYCHAIN_ITEM`). Положить в Keychain:

```bash
security add-generic-password -a wbfbs -s wb-fbs-token -w '<токен>' -U
```

Токен создаётся в кабинете селлера: seller.wildberries.ru → Профиль →
Настройки → Доступ к API → категория «Маркетплейс».

## Цикл сборки поставки

```bash
wbfbs orders new                                    # новые задания (+требуемая маркировка)
wbfbs supply create --name "Поставка 06.07"        # -> WB-GI-...
wbfbs supply add WB-GI-123 --orders 111,222,333    # bulk по 100, new -> confirm
wbfbs labels --orders 111,222,333 -o labels.pdf     # 58x40 | 40x30, --a4 для сетки
wbfbs boxes create WB-GI-123 --count 3              # короба (поставки на ПВЗ)
wbfbs boxes stickers WB-GI-123 -o boxes.pdf         # стикеры коробов 580x400
wbfbs supply deliver WB-GI-123                      # закрыть (необратимо, спросит)
wbfbs supply qr WB-GI-123 -o supply_qr.pdf          # QR — ТОЛЬКО после deliver
```

Порядок не случаен: WB отдаёт QR поставки только после передачи в доставку,
а этикетки заказов — только в статусе confirm (после добавления в поставку).

## Что важно знать про API (сверено со спекой 2026-07-02)

- Эндпоинты сверены с официальной OpenAPI-спекой: dev.wildberries.ru
  (зеркало `github.com/eslazarev/wildberries-sdk`, specs/03-orders-fbs.yaml).
- Одиночные методы добавления/чтения заказов поставки WB **удалил
  17–18.12.2025** — используются bulk-методы `/api/marketplace/v3/...`
  (до 100 ID за запрос). Интеграции на старых путях мертвы — это одна из
  причин, почему сейчас столько сломанных модулей.
- **Раскладки заказов по коробам в API нет** — только создание N коробов,
  их стикеры и удаление. Обещать клиенту «привязку заказов к коробам через
  API» нельзя.
- Rate-limit единый на все FBS-методы: 300 req/мин, интервал 200 мс
  (клиент троттлит сам). Ответ 4XX списывает лимит **как 10 запросов**,
  поэтому 4XX не ретраится — только 429/5xx.
- 409 — всегда семантика, не гонка: смешение габаритных типов
  (cargoType) или складов в поставке, закрытая поставка, непрошедшая
  маркировка на deliver (тело содержит разбор по каждому заказу).
- Есть песочница `marketplace-api-sandbox.wildberries.ru` — полный цикл
  можно прогнать без боевого кабинета: `export WB_API_BASE=<sandbox-url>`.

## Гочи кабинета (добыто опытом)

- Свежий кабинет отдаёт `403 AccessDenied` на весь marketplace-api, пока
  в ЛК не выбраны **минимум 5 пунктов возврата** (Поставки и заказы →
  Склад продавца → FBS → «Select an outlet»). Создание склада для доступа
  к API не требуется.
- Песочница: `make` принимает `{"orders":[{"sku":"<баркод>","amount":N}]}`
  (sku = баркод карточки, amount = число СЗ ≤ 10); остатки — только по
  chrtId; повторная установка той же цены — ошибка «already set» (норма).

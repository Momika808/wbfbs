403 Access denied на весь Marketplace API Wildberries — причина не в токене

Проверено на живом кабинете, июль 2026

Симптом: свежий кабинет продавца, токен создан, категория «Маркетплейс» отмечена, GET /ping отвечает 200 — а любой метод marketplace-api.wildberries.ru возвращает:

{"code":"AccessDenied","message":"Access denied"}

Причём 403 отдаёт весь домен целиком — даже безобидный GET /api/v3/warehouses (список складов), который от заказов никак не зависит. При этом общие методы работают: например, common-api.wildberries.ru/api/v1/seller-info спокойно отвечает 200 тем же токеном.

Что это НЕ

  • Не скоуп токена — категория «Маркетплейс» на месте, пересоздание не помогает.
  • Не тип токена — «Персональный» и «Базовый» ведут себя одинаково.
  • Не задержка активации токена.
  • Не код и не заголовки — те же запросы работают в песочнице.

Причина

FBS-контур кабинета выключен, пока продавец не выберет минимум 5 пунктов выдачи для возвратов. Пока это не сделано, WB блокирует весь marketplace-домен на уровне кабинета — показательно, что собственный веб-интерфейс WB в этом состоянии ловит тот же «Access denied» на своих же внутренних запросах (красные тосты в разделе настроек FBS).

Решение (2 минуты)

  1. Кабинет WB Партнёры → Поставки и заказы → Склад продавца → FBS (или «Склады и пропуска» / «Настройки» — любой из них покажет заглушку «выберите пункт выдачи»).
  2. Кнопка выбора ведёт в раздел возвратов → форма «Пункт выдачи возврата».
  3. Выберите 5 адресов ПВЗ (логично — ближайшие к вам: туда поедут возвраты, если появятся продажи) → Сохранить.

После сохранения 403 снимается сразу, все методы начинают отвечать 200. Проверено изоляцией: создавать склад продавца для доступа к API не нужно — склад понадобится только для реальных заказов; выбора пунктов возврата достаточно.

Как проверить

curl -H "Authorization: $WB_TOKEN" \
  https://marketplace-api.wildberries.ru/api/v3/warehouses
# до фикса:  403 {"code":"AccessDenied"...}
# после:     200 []

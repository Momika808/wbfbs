Остатки WB перестали грузиться по баркоду: теперь только chrtId

Сверено с официальной OpenAPI-спекой, снимок 2026-07-02

Симптом: PUT /api/v3/stocks/{warehouseId} с привычным телом по баркоду возвращает безликое:

400 {"code":"IncorrectRequest","message":"Incorrect Request"}

по которому причину не угадать. Причина: с миграции февраля 2026 остатки привязываются только к chrtId — ID размера товара. Загрузка по баркоду (sku) отключена: в спеке метода теперь отдельный пример ошибки SKUUploadDisabled.

Как правильно

PUT /api/v3/stocks/{warehouseId}
{"stocks": [{"chrtId": 336044, "amount": 10}]}
→ 204

Где взять chrtId

В карточке товара (Content API): POST /content/v2/get/cards/list — у каждого размера в sizes есть и chrtID, и баркоды skus. Важно не перепутать назначение:

  • остатки — по chrtId;
  • этикетки, сборочные задания — там по-прежнему живут баркоды (sku);
  • это разные сущности в разных методах, и API нигде прямо не говорит, какая где нужна.

Это ровно та миграция, из-за которой зимой–весной 2026 в ветках интеграционных модулей стояла паника «обмен остатками сломался». Лечится за час, когда знаешь; выглядит как необъяснимый отказ, пока не знаешь.

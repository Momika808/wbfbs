Интеграция перестала собирать поставки WB? В декабре удалили методы

Сверено с официальной OpenAPI-спекой, снимок 2026-07-02

17–18 декабря 2025 Wildberries удалил из Marketplace API два метода, на которых держались почти все интеграции FBS:

  • PATCH /api/v3/supplies/{supplyId}/orders/{orderId} — одиночное добавление заказа в поставку (удалён 18.12.2025);
  • GET /api/v3/supplies/{supplyId}/orders — заказы поставки (удалён 17.12.2025).

Код, написанный по гайдам старше зимы 2025-го, просто перестал работать — и сообщение об ошибке не подсказывает, что методы переехали.

Замена

Добавление заказов — теперь bulk, до 100 ID одним запросом:

PATCH /api/marketplace/v3/supplies/{supplyId}/orders
{"orders": [111111, 222222, 333333]}
→ 204

Бонус миграции: заказы при добавлении автоматически переходят из new в confirm — отдельный шаг подтверждения больше не нужен. Вся дневная партия — одна операция вместо «3–4 запроса на заказ».

Заказы поставки — теперь только ID:

GET /api/marketplace/v3/supplies/{supplyId}/order-ids
→ {"orderIds": [111111, 222222]}

Полные данные заказов добираются через GET /api/v3/orders.

Три вещи, которые сломают вам ретраи

  • Лимит на все FBS-методы общий: 300 запросов/мин на аккаунт, интервал 200 мс. Ответ 4XX списывается как 10 запросов — цикл, ретраящий ошибки в лоб, выжирает лимит в десять раз быстрее. Ретраить можно только 429 и 5xx.
  • 409 на добавлении — это семантика, не гонка: смешение габаритных типов (поставка наследует cargoType первого заказа), заказы с разных складов, внутренние + трансграничные вперемешку, закрытая поставка.
  • QR поставки (GET .../barcode) отдаётся только после передачи в доставку (PATCH .../deliver) — напечатать «заранее» нельзя.

Всё это уже учтено в wbfbs — открытом инструменте сборки FBS-поставок (короба, стикеры, этикетки одним PDF, QR). Нужна миграция вашей интеграции или внедрение под ключ — TG @wallbon.
